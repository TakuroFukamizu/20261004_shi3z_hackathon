# toio 9 台制御 設計書

- 日付: 2026-10-04
- 状態: 実装済み（単体テスト通過、実機未確認）。コマンド仕様は README を正とする

## 1. 目的

toio コア キューブ 9 台を、Mac 上の AI やスクリプトから「3 番を (x, y) へ」のような
高レベル命令で随時動かせるようにする。StackChan + RoverC とは独立した系統で、Core2 は経由しない。

### ユーザーが明示した要件

- StackChan とは別に、toio を 9 台制御する
- 用途は AI やスクリプトからの自由な指示（振り付けの再生や手動操縦が主目的ではない）
- toio 開発用プレイマット（TMD01SS-A）1 枚の上で使う。A3 で 7 × 5 マスの面
- ホストは Mac のみで始める。9 台が安定しなければ ESP32 ブリッジに切り替えてよい

### こちらで置いた前提（レビューで訂正してください）

| # | 前提 | 根拠 |
|---|------|------|
| A1 | キューブのファームウェアは目標指定付きモーター制御に対応している | 対応していない個体は `move` が使えない。検証手順で BLE プロトコルバージョンを読んで確認する |
| A2 | 使うのは表面（7 × 5 マスの簡易プレイマット面）で、座標は (98, 142)〜(402, 358) | 参考仕様図では #01〜#06 の表面がこのマス目の面。実機の `status` で四隅の座標を確認する |
| A3 | 呼び出し側は同じ Mac 上にいる | ハブは localhost だけで待ち受ける |
| A4 | キューブに 1〜9 の番号シールを貼る | 外見が同じため |

## 2. 調査で確定した事実

- キューブは BLE ペリフェラル。サービス UUID は `10B20100-5B3B-4571-9508-CF3EFCD7BBAE`。
  使う characteristic は読み取りセンサー `10B20101`、モーター `10B20102` と、ランプ、サウンド、
  バッテリー、設定（UUID は実装時に仕様書から転記する。末尾以外は共通）。
- 広告のローカルネームは `toio-XXX`（旧ファームは `toio Core Cube-XXX`）。`XXX` は個体ごとの
  3 文字で、ホストが変わっても同じ。macOS では MAC アドレスが取れないが、この名前で個体を識別できる。
- **目標指定付きモーター制御**（モーター characteristic に 13 バイト、種類 `0x03`）:
  制御 ID、タイムアウト（秒、0 は 10 秒）、移動タイプ（0: 回転しながら、1: 後退なし、2: 回転してから）、
  最大速度 10〜255、速度変化タイプ、X、Y、角度（各 UInt16 LE）。キューブが自律で走り、
  結果を notify（`0x83`、制御 ID、応答コード）で返す。

  | コード | 意味 |
  |--------|------|
  | 0x00 | 到達 |
  | 0x01 | タイムアウト |
  | 0x02 | マットを見失った |
  | 0x03 | パラメータの組み合わせが不正 |
  | 0x04 | 状態が不正 |
  | 0x05 | 別の書き込みで中断 |
  | 0x06 | 非対応 |

- 位置は読み取りセンサーの notify（種類 `0x01`、キューブ中心 X、Y、角度）。マットから外れると `0x03`。
- **開発用プレイマット（TMD01SS）**: A3（420 × 297 mm）の 12 枚組で、表と裏で座標が違う。
  - **表面（#01〜#06）は簡易プレイマット**: 7 × 5 のマス目が印刷されている。座標は 6 枚とも同じで
    左上 (98, 142)、右下 (402, 358)。304 × 216 単位なので、1 マスは約 43.4 × 43.2 単位（60 mm 角）。
    今回使うのはこの面。
  - 表面（#07〜#12）は簡易カードで、位置は取れない。
  - 裏面は連番マット。12 枚で X 34〜949、Y 35〜898 の連続した座標系になる（#01 は (34, 35)〜(339, 250)）。
    今回は使わない。
  - 換算は約 1.38 mm / 単位。キューブ（約 32 mm 角）は約 23 単位で、1 マスに 1 台が収まる。
  - 表面と裏面の座標範囲は重なるため、位置からどちらの面かを自動判定することはできない。

- Mac（CoreBluetooth）の同時接続数の上限は非公開で、機種と OS によって変わる。
  toio.py の公式サンプルは 2 台まで。9 台の安定性は実測でしか分からない。

### 実機でしか確認できない点

1. この Mac から 9 台に同時接続して維持できるか。
2. 9 台へ順に書き込んだときの 1 台あたりの遅延。
3. 9 台分の位置 notify を受け続けても取りこぼしや切断が起きないか。
4. 全台のファームウェアが目標指定付きモーター制御に対応しているか。

## 3. 全体構成

```
AI / スクリプト ──HTTP (127.0.0.1)──▶ toio ハブ（常駐、Python + bleak）──BLE × 9──▶ キューブ 1〜9
   └ client/toio.py（CLI 兼ライブラリ、標準ライブラリのみ）
```

BLE の接続確立は 1 台あたり秒単位かかるので、コマンドのたびに接続する方式は取らない。
ハブが 9 接続を保持し続け、CLI とライブラリはハブに HTTP で話すだけにする。

```
client/
  toio.py            CLI 兼ライブラリ。robot.py と同じ流儀で、標準ライブラリのみ
  toio_hub.py        常駐ハブ。uv のスクリプトメタデータで bleak を宣言（presenter.py と同じ方式）
  toio_protocol.py   バイト列の組み立てと解釈。純粋関数のみで BLE に依存しない
  toio_field.py      マット範囲、マスと座標の変換、目標の検査。純粋関数のみ
  toio_spike.py      9 台同時接続の検証スクリプト
  toio_config.json   マット範囲、キューブ名と番号の対応（git 管理する）
  test_toio.py       toio_protocol、toio_field、toio.py の単体テスト
  test_toio_hub.py   ハブのコマンド処理、設定読み込み、HTTP の単体テスト
```

## 4. モジュール

### toio_protocol
命令のバイト列を作る関数と、notify を解釈する関数だけを持つ。
目標指定移動、直接駆動、ランプ、サウンド、位置、応答コード、バッテリー。BLE なしでテストできる。

### toio_hub
- **接続**: 起動時にサービス UUID でスキャンし、設定にある名前のキューブへ 1 台ずつ順に接続する。
  同時に接続を始めると失敗しやすいため直列にする。切れたキューブはバックグラウンドで再接続を試み続ける。
- **状態**: キューブごとに、接続中か、最新の位置と角度、マット上か、バッテリー、実行中の移動を持つ。
- **書き込み**: キューブごとに直列化する。別のキューブへの書き込みは並行に出す。
- **移動の完了待ち**: 制御 ID を命令ごとに振り、同じ ID の応答 notify が来るまで待つ。
  応答が来ないまま「タイムアウト + 2 秒」を過ぎたら失敗として返す。
- **HTTP**: `127.0.0.1:8765` で `POST /cmd` を受ける。応答は `{"ok":true,...}` か `{"ok":false,"error":"..."}`。

### コマンド

| cmd | 引数 | 動作 |
|-----|------|------|
| `status` | なし | 全台の `connected` `x` `y` `angle` `on_mat` `battery` `busy` |
| `move` | `id` `x` `y`、任意で `angle` `speed`（既定 80）`timeout`（既定 10） | 目標へ走らせ、到達か失敗まで待って結果を返す |
| `move_all` | `targets`: `[{id, x, y, angle?}]`、任意で `speed` `timeout` | 全台に発行し、全台の結果をまとめて返す |
| `drive` | `id` `left` `right`（-115〜115）`ms`（最大 2550） | 時間指定の直接駆動。マット外でも使える |
| `led` | `id` `r` `g` `b`、任意で `ms` | ランプ |
| `sound` | `id` `effect`（0〜10） | 内蔵の効果音 |
| `identify` | `id` | 3 秒間ランプを点滅させ音を鳴らす |
| `stop` | 任意で `id` | 指定台、または全台を停止。実行中の `move` は「中断」で返る |

`move` と `move_all` の目標は、座標 `x` `y` の代わりにマス `col`（1〜7、左から）と `row`（1〜5、上から）
でも指定できる。ハブがマスの中心座標に変換する。`status` は各台の `col` `row` も返す。

`id` は 1〜9。`drive` `led` `sound` `stop` は `id` に `"all"` も取れる。
`move` と `move_all` は `"wait": false` を付けると発行だけして即座に返る。結果は `status` の `busy` と
`last_result` で見る。

### 目標の検査（発行前にハブが行う）

- 目標がマット範囲から余白 15 単位以上内側にあること（端のマスの中心は端から約 22 単位で、これを満たす）。
- 目標が、他のキューブの現在地および実行中の目標から 35 単位（約 48 mm）以上離れていること。
  `move_all` では同じ命令に含まれる目標同士も検査する。
- 対象が接続中でマット上にいること。

どれかに反したら何も動かさずにエラーを返す。経路同士の交差は検査しない（7 章）。

### toio.py（CLI 兼ライブラリ）

```sh
uv run client/toio_hub.py                 # ハブを起動（このターミナルに接続状況が出る）
python3 client/toio.py status
python3 client/toio.py move 3 --cell 4,2          # 4 列目、2 行目のマスの中心へ
python3 client/toio.py move 3 --xy 250,250 --angle 90
python3 client/toio.py move-all 1:1,1 2:2,1 3:3,1    # 番号:列,行
python3 client/toio.py led all 0 255 0
python3 client/toio.py identify 5
python3 client/toio.py stop
```

```python
from toio import Toio
t = Toio()
t.move(3, cell=(4, 2))
t.move(3, xy=(250, 250), angle=90)
t.move_all({1: (1, 1), 2: (2, 1)})        # マス指定
```

### 番号の割り当て

`uv run client/toio_hub.py --assign` で対話的に行う。見つかったキューブを 1 台ずつ光らせ、
ユーザーが入力した番号を `toio_config.json` に `{"name": "toio-a1B", "id": 3}` の形で保存する。

### 設定ファイル

```json
{
  "mat": {"x_min": 98, "y_min": 142, "x_max": 402, "y_max": 358, "cols": 7, "rows": 5},
  "cubes": [{"name": "toio-a1B", "id": 1}]
}
```

`mat` の初期値は開発用マット表面（簡易プレイマット）の 1 枚分。別のマットに替えるときはここを書き換える。
`cols` と `rows` を省くとマス指定は使えず、座標指定だけになる。

マスは 35 個で、キューブは 9 台。隣のマスの中心同士は約 43 単位離れていて、目標の検査の
35 単位を満たす。つまり「1 マスに 1 台」なら隣り合って置ける。

## 5. エラー処理と安全

- 接続できないキューブがあってもハブは起動し、つながった台だけで動く。`status` で分かる。
- 不正なコマンドや検査に反した目標はエラーを返し、どのキューブも動かさない。
- 移動中にキューブがマットから外れると、キューブ自身が止まり、応答コード 0x02 が返る。
- ハブの終了時（Ctrl-C を含む）に全台へ停止を送る。
- ハブが異常終了しても、目標指定移動はキューブ側のタイムアウトで止まり、`drive` は指定時間で止まる。
  時間無制限の駆動命令は提供しない。

## 6. テストと進め方

1. **検証（最初の関門）**: 使い捨てスクリプトで 9 台に接続し、順にランプを点け、
   書き込み遅延、位置 notify の受信、10 分間の切断回数を測る。BLE プロトコルバージョンも読む。
   合格の目安は、10 分間で切断 0 回、書き込み遅延が 1 台あたり 100 ms 未満。
2. **合格した場合**: この設計書のとおり実装する。
3. **不合格の場合**: ハブの BLE 部分だけを ESP32 ブリッジ（1 台あたり 3 台を担当）に置き換える。
   `/cmd` の仕様は変えないので、`toio.py` と呼び出し側はそのまま使える。ブリッジの設計は別途行う。

- **単体テスト**: `toio_protocol` のバイト列（仕様書の例と照合）、応答コードの解釈、目標の検査。
- **実機確認**: `identify` で番号が合うこと、`move` が到達を返すこと、マット範囲外と近接目標が拒否されること、
  `stop` で全台が止まること。実機確認はユーザーが行う。
